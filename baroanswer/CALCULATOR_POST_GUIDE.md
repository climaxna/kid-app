# 바로답 계산기 소개 글 작성 규칙

사용자가 검수를 마친 네 편을 기준으로 삼는다.
- `20260925-parental-leave-calculator.md`
- `20260925-net-salary-calculator.md`
- `20260925-unemployment-benefit-calculator.md`
- `20260925-severance-calculator.md`

새 글은 이 네 편의 형식, 길이, 말투를 따른다. 공통 문체와 강조 문법은 `C:\blog\CONTENT_GUIDE.md`를 따른다(`<!-- info -->` 프로파일, 한 줄 20~28자, 2~4줄 묶음, 강조 4종, 이모지 금지, 소제목은 밑줄 인용구).

## 1. 쓰기 전에: 계산기와 법령 원문 대조 (생략 금지)

검수한 네 편 중 세 편에서 사이트 계산기 오류가 나왔다. 이 단계가 글의 신뢰를 지킨다.

1. `C:\portal`에서 계산기 파일을 찾는다: `src/app/{카테고리}/{도구}/page.tsx`, `src/components/*Calculator.tsx`, `src/lib/*.ts`, `src/config/*.ts`
2. 계산식, 비율, 상한과 하한, 기준 연도 값을 모두 적어 둔다.
3. 법령 원문(law.go.kr 조문 원문 HTML), 찾기쉬운 생활법령, 부처 고시로 하나씩 대조한다. 검색 요약본만 보고 판단하지 않는다. 요약본이 분수나 숫자를 틀리게 준 적이 있다(1/2를 0.005로 옮긴 오류가 그렇게 생겼다).
4. **사이트가 틀렸으면 글을 쓰지 않는다.** 대신 `baroanswer/site-issues/YYYYMMDD-{도구}.md`에 오류 보고서를 남기고 카탈로그 상태를 `보류 (사이트 오류)`로 바꾼 뒤 보고한다. 보고서에는 조문 원문 문구, 사이트 코드 위치와 현재 식, 틀린 예시 한 줄을 넣는다. 사이트 수정과 배포는 사용자 확인을 받고 사람이 진행한다.
5. 확정하지 못한 값은 글에 넣지 않는다.

## 2. 예시 숫자는 사이트 함수로 뽑는다

표와 예시의 숫자는 머리로 계산하지 않는다. 사이트의 계산 함수를 그대로 호출해서 뽑는다. 그래야 글과 계산기 결과가 어긋나지 않는다.

```bash
cd /c/portal && npx --yes tsx <스크래치 경로>/example.ts
```

`example.ts`에서는 `C:/portal/src/lib/...`를 import한다. 경로 별칭(`@/`) 때문에 반드시 `C:\portal`에서 실행한다.

## 3. 글 구조

| 순서 | 내용 |
|---|---|
| 제목 | `{계산기 이름 또는 주제} 2026 {궁금증 한 줄}`. 특수문자 없이 쓰고, 숫자가 들어간 구체적 질문으로 만든다 |
| 도입 | 독자가 가장 궁금한 질문을 한 줄로 던지고, 흔한 오해를 한 번 뒤집는다 |
| 요약 박스 | `<!-- box: quotation_corner -->` 3~4줄로 핵심 숫자를 먼저 보여준다 |
| 대상과 조건 | 누가 받는지, 누가 해당되는지 bullet로 |
| 계산 방식 | 공식은 인용 한 줄로, 구성 요소는 쉬운 말로 |
| 예시 표 | 금액별·기간별 표 1~2개. 롱테일 검색어(예: "연봉 4000 실수령액")를 표로 잡는다 |
| 조건 바꿔 보기 | 입력 하나를 바꿨을 때 달라지는 표. 계산기를 써 보고 싶게 만드는 부분이다 |
| 알아둘 점 | 신청 기한, 지급 기한, 세금, 흔한 실수 |
| 계산기 소개 | `<!-- box: quotation_postit -->`로 입력 단계와 결과 항목을 보여주고, 계산기 링크 1개와 관련 계산기 링크 1개 |
| 출처 | 기준일, 법령 원문 URL, 바로답 URL, 한 줄 면책 |
| 태그 | 20~30개. 마지막에 `#생활계산기 #바로답 #계산기` |

- 분량은 표를 포함해 원고 약 150~200줄이다.
- 궁금증 요소를 본문에 최소 하나 넣는다. 예: "월급 330만 원 이하면 모두 같은 금액", "1년에서 4일 모자라면 0원", "250만 원을 넘으면 1년 합계가 같다".

## 4. 사이트 홍보 규칙

- "제가 만든 무료 계산기 사이트 **바로답**"이라는 표현은 글에서 한 번만 쓴다.
- 링크는 계산기 1개와 관련 계산기 1개까지만 넣는다. 외부 링크가 많으면 홍보 글로 보인다.
- 계산기 없이 읽어도 쓸모 있는 글이어야 한다. 제도 설명이 주인공이고 계산기는 도구다.
- 도입 첫 문장과 마무리 문장은 글마다 다르게 쓴다. 같은 틀이 매일 반복되면 네이버가 도배로 볼 수 있다.

## 5. 이미지: 실제 바로답 화면 캡처 2~3장

**썸네일과 그 밖의 블로그 이미지는 만들지 않는다.** 사용자가 직접 만든다(2026-09-25 결정: 코드로 만든 썸네일은 품질이 떨어진다). 자동으로 넣는 것은 실제 바로답 사이트 화면 캡처뿐이다.

| 캡처 | 개수 | 넣는 위치 |
|---|---|---|
| 계산기 입력과 결과 | 1장 (필수) | 계산기 소개 박스 설명이 끝나고 계산기 링크가 나오기 전 |
| 계산기 아래 "핵심 비교" 차트 | 1~2장 | 그 차트와 같은 내용을 설명하는 본문 섹션의 끝 |

- 차트는 **원고의 섹션과 내용이 맞는 것만** 고른다. 예: 퇴직금 글은 "하루 더 다니면" 섹션에 근속별 차트, "상여금이 있으면" 섹션에 평균임금 구성 차트를 넣었다.
- 맞는 차트가 없으면 계산기 캡처 1장만 넣는다. 전체 캡처는 3장을 넘기지 않는다.
- "다음 계산" 카드처럼 다른 계산기로 보내는 영역은 찍지 않는다.

1. `baroanswer/images/{도구 slug}.json`에 spec을 만든다. 형식은 `scripts/baroanswer_images.example.json`을 따른다.
   - `outDir`: `assets/posts/baroanswer-{도구 slug}`
   - 계산기 캡처: `{"file": "01-calculator.png", "url": ..., "fill": {...}}`
   - 차트 캡처: `{"file": "02-compare-....png", "url": ..., "fill": {...}, "figure": "차트 제목 앞부분"}`
   - 차트 제목은 계산기 코드의 `title="..."`(ComparisonBars, StackedBreakdown, TrendLineChart)에서 찾는다.
   - `fill`의 라벨은 계산기 코드의 `label="..."`와 정확히 같게 쓴다. 캡처에 보이는 숫자가 원고의 예시 숫자와 같아지도록 값을 넣는다.
2. `node scripts/baroanswer_images.mjs baroanswer/images/{도구 slug}.json`을 실행한다.
3. 캡처를 **모두 직접 열어 확인**한다. 숫자가 원고와 같은지, 차트 내용이 넣을 섹션과 맞는지 본다. 다르면 spec을 고쳐 다시 찍는다.
4. 원고의 각 위치에 ``📷 [실제사진 N] 파일: `assets/posts/baroanswer-{slug}/파일명.png` `` 한 줄씩 넣는다. N은 원고에 나오는 순서대로 1부터 매긴다. 예시는 `20260925-severance-calculator.md`를 본다.
5. 원고에 다른 이미지 표시나 사진 자리 표시는 넣지 않는다.

## 6. 저장

1. `python -X utf8 scripts/blog_pipeline_check.py baroanswer/<파일>.md --content-type ferry_info --stage local`
2. `python -X utf8 scripts/naver_blog_draft.py --markdown-file baroanswer/<파일>.md --with-images` (한 번만)
3. 카테고리는 사용자가 네이버에서 "생활계산기"로 직접 옮긴다.
4. `CALCULATOR_CATALOG.md`의 상태를 `임시저장`으로 바꾸고 원고 파일명을 적는다.
5. 발행은 하지 않는다.
