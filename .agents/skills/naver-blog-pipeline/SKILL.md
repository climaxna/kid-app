# 네이버 블로그 통합 제작

사용자의 한 번의 주제 요청으로 로컬 원고와 이미지를 완성하고 네이버 임시저장까지 진행한다.
최종 발행은 사용자에게 남긴다.

## 시작할 때

작업 공간 루트에서 다음 파일을 읽는다.

1. `BLOG_PIPELINE_CONFIG.json`
2. `BLOG_STRATEGY.md`
3. `CONTENT_GUIDE.md`
4. `IMAGE_STYLE_PRESETS.md`
5. 육아 글이면 `PARENTING_EXPERIENCE_PROFILE.md`

현재 글을 `island_compare`, `ferry_info`, `parenting_info`, `parenting_diary`,
`product_review` 중 하나로 분류하고 설정의 디렉터리·스타일·이미지 프리셋·이미지 수를 적용한다.

## 입력 판단

- 정보형 글과 섬 비교 글은 주제만으로 진행한다. 최신 정보는 공식 1차 자료를 우선 조사한다.
- 육아 정보 글은 보편적인 정보로 작성할 수 있다. 사용자 검토용 경험 문단은
  `<!-- experience -->` 다음 줄의 인용문으로 내부 구분하고, 네이버 본문에는
  `경험담 초안` 같은 접두어를 표시하지 않는다. 확인되지 않은 세부 사실을 실제 경험으로
  확정해 단정하지 않는다.
- 육아 일기와 내돈내산 제품 리뷰처럼 실제 사실이 글의 핵심인 경우, 확인된 경험이나 제품
  사진이 없으면 사실을 만들지 않는다. 결과를 크게 바꾸는 정보 한 가지만 짧게 확인한다.
- 실제 사진이 첨부되면 기본은 `REAL_PHOTO_REFERENCE`다. 원본 사용·직접 편집은 사용자가
  명시했을 때만 한다.

## 제작 순서

1. 내부적으로 독자, 검색 질문, 핵심 키워드, 사실 검증 항목, 본문 구조를 정한다.
2. 변동 가능 정보와 건강·안전 정보는 최신 공식 자료를 확인하고 기준일과 출처를 남긴다.
3. 유형에 맞는 스타일 지시자를 포함해 로컬 Markdown 원고를 작성한다.
4. 완성된 원고에서 주요 소제목별 이미지 역할을 정하고, 글과 별도로 이미지 매니페스트를
   만든다. 형식은 [references/image-manifest.md](references/image-manifest.md)를 따른다.
5. 해당 프리셋을 적용해 대표 이미지와 단락 이미지를 모두 생성한다. 섬 비교는
   `대표 썸네일 → 한눈에 비교 → 대표 관광지 → 최종 추천` 역할의 독립된 1:1 이미지
   4장을 각각 생성한다. 육아 정보 글도 `대표 썸네일 → 핵심 생활 장면 → 핵심 정보 →
   요약·추천` 4장을 기본으로 한다. 사용자가 `다음`이나 이미지 번호를 입력할 때까지
   기다리지 않는다. 생성·사진참고 이미지에 인물이 나오면 `IMAGE_STYLE_PRESETS.md`의
   1980년대 한국 일상 인물 스타일을 적용하되, 시설·정보·제품·육아 안전은 현재 기준을
   유지한다. 실제 사진 직접 편집은 명시적 요청 없이 시대 스타일로 바꾸지 않는다.
   배편·제주 여행 시리즈에서는 설정에 등록된 고정 여성 진행자 페르소나를 초반 `한눈에 보기`와
   후반 `최종 선택` 정보 이미지에 각각 한 번씩, 총 2장 사용한다. 실제 항구·배경 앞의 사진형
   진행 장면은 만들지 않는다. 그 밖의 단일 섬 소개·섬 비교 글은 기본 1장을 유지한다.
   화면 한쪽의 작은 반신 진행자와 반대쪽의 본문 핵심 카드로 구성한다. 설정에 등록된 참고
   원본에서는 얼굴의 기본 형태와 이목구비 관계만 유지하고, 헤어·의상·액세서리·포즈·배경·
   분위기는 글마다 바꾼다. 같은 글의 두 진행자 이미지에는 서로 다른
   절제된 편집 효과를 사용한다. 배편 정보글은 한눈에 보기 외에 차량 선적·요금·항구 선택처럼
   비교가 필요한 핵심 내용을 최소 1개의 별도 도표 이미지로 만들고, 본문 표와 함께 제공한다.
6. 실제 사진을 사용할 때는 개인정보와 얼굴 공개 범위를 먼저 확인한다. 원본과 생성·편집
   결과는 `private_media/` 또는 `assets/posts/` 아래에만 둔다.
7. 이미지마다 한글, 인물·손발, 쌍둥이 수, 장소 특징, 안전한 육아 자세, 비율과 개인정보를
   내부 검수한다. 섬 비교는 4장이 각각 독립 파일인지, 모두 정사각형인지, 사진이 시각적
   중심인지도 확인한다. 문제가 있는 이미지만 다시 생성한다. 생성 이미지의 원본 바이트나
   미리보기는 채팅에 싣지 않고, 사용자는 이미지가 포함된 네이버 임시글에서 최종 검수한다.
8. 원고의 해당 소제목 바로 아래 또는 첫 설명 문단 뒤에 로컬 이미지 표시를 넣는다.
9. `python -X utf8 scripts/blog_pipeline_check.py <원고> --content-type <유형> --stage naver`
   로 품질 관문을 통과시킨다.
10. `python -X utf8 scripts/naver_blog_draft.py --markdown-file <원고> --with-images`로 이미지가
    포함된 네이버 임시글을 한 번 만든다.
11. 임시저장 성공 여부, 제목, 이미지 수와 확인이 필요한 경험 위치를 사용자에게 보고한다.

이미지 생성 도구의 결과를 처리할 때는 파일 경로와 완료 상태만 사용한다. 이미지의 base64나
대용량 원본 데이터를 출력·직렬화하지 않으며, 사용자가 명시적으로 요청하지 않는 한 채팅에
이미지 미리보기를 표시하지 않는다.

## 로컬 이미지 표시

로컬 원고에 다음 중 하나를 한 줄로 넣는다. 이 줄은 네이버 임시저장 때 실제 이미지와 안내
문구로 바뀐다.

```text
📷 [생성이미지 1] 파일: `assets/posts/<slug>/01-thumbnail.png`
📷 [실제사진 1] 파일: `private_media/<slug>/01.jpg`
📷 [편집사진 1] 파일: `assets/posts/<slug>/01-edited.png`
```

`REAL_PHOTO_REFERENCE` 결과는 실제 사진이 아니라 `생성이미지`로 표시한다.
생성 이미지 아래에는 별도의 생성 이미지 안내 문구를 자동으로 붙이지 않는다.

## 완료 조건과 중단 조건

- 이미지용 프롬프트·브리프·매니페스트를 네이버 본문에 넣지 않는다.
- 필수 이미지가 없거나 검사에 실패하면 네이버에 불완전한 새 임시글을 만들지 않는다.
- 쿠키가 만료되면 로컬 결과를 보존하고 쿠키 갱신만 요청한다.
- 임시저장 후에도 발행하지 않는다. 사용자의 명시적인 별도 요청과 최종 확인 없이는 공개
  상태를 변경하지 않는다.
