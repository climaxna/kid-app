# 재유행 쇼츠에서 원본을 찾아 제작하는 수동 루틴

현재 모드: 수동 실행. 사용자가 예약을 요청하기 전에는 스케줄을 등록하지 않는다.

1. 사용자 기준 한국 날짜로 `python radar.py --date YYYY-MM-DD` 실행. 하루 조사 결과를 캐시하며 원본 영상은 내려받지 않는다. 현재 6개 검색어 × 최대 12개, 상세 확인 최대 8개로 제한한다. Shorts 전용 필터는 수집기에서 결과가 누락되어 일반 관련성 검색의 180초 이하 후보로 대체한다. 이것만으로 Shorts나 최근 업로드로 확정하지 말고 상세 날짜와 실제 Shorts 화면을 확인한다. 최근 7일 업로드가 확인되지 않으면 신규 급증 후보로 채택하지 않는다.
2. 당일 `radar/YYYY-MM-DD/brief.md`와 필요할 때만 `snapshot.json`을 읽는다. 같은 작품의 다른 제목·배우명을 묶고 다른 채널에서 반복되는 장면을 찾는다. 후보 제목만 보고 작품을 확정하지 않는다.
3. 처음 관측하면 기준선으로 기록한다. 쇼츠 누적 조회수가 높다는 이유만으로 최근 급증이라 부르지 않는다. 이후 동일 검색 조건의 기록과 비교해 새로 발견된 영상, 서로 다른 채널 수, 동일 영상의 조회수 증가를 근거로 선정한다. 검색 표본의 변화는 유튜브 전체 업로드량 증가와 다르다. 검색 실패나 검색어 변경은 비교에 명시한다.
4. 최대 3개 작품 중 1개를 선택한다. 근거가 부족하면 '제작 흐름 시험용'이라고 표시하고 급증 후보와 구분한다. 예전 작품 여부는 원방송/개봉 정보를 확인한다.
5. 해당 장면의 공식 방송사·배급사 원본을 찾는다. 공식 채널 근거와 쇼츠-원본의 장면 일치를 확인한다. 타인의 쇼츠를 제작 원본으로 다운로드하지 않는다. 공식 원본이 없거나 접근 제한이 있으면 사유를 기록하고 다른 후보로 이동한다. 조회 가능한 것과 재사용 허가는 별개다.
6. 원본 1개만 `pipeline.py prepare URL`로 내려받고 인식한다. 비용 절약을 위해 가급적 20분 이하 공식 하이라이트를 고른다. 기존 캐시와 `produced.json`의 원본 ID·시간 구간을 확인해 중복 제작을 피한다.
7. 원본 대사와 장면을 확인해 독립적으로 이해되는 15~35초 구간을 최대 2개 고른다. 구간을 억지로 두 개 채우지 않는다. 제목과 상황 자막은 새로 작성한다. 다른 쇼츠의 제목·자막을 복제하지 않는다.
8. 설정 JSON을 저장하고 `pipeline.py render` 또는 `batch`로 제작한다. 자동 디코딩 검사와 대표 화면 확인 후 MP4 경로를 기록한다. 오인식, 대사 잘림, 결말 누락을 확인한다.
9. `radar/YYYY-MM-DD/result.md`에 발견 근거, 첫 관측/증가 여부, 공식 원본, 편집 구간, 결과 파일, 한계 및 다음 관측 사항을 기록한다. `produced.json`에도 원본 ID와 구간을 추가한다.

사용량 절약: 조사·영상 정보 수집·음성 인식·렌더링은 로컬 프로그램, 작품 식별·장면 선택·제목 작성은 Codex가 맡는다. 조사와 판단에 쓰는 Codex 사용량은 발생한다. 후보가 없을 때 검색을 무제한 확대하지 말고 부족한 근거를 보고한다. 외부 업로드와 발행은 하지 않는다.
